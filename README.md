# Stablecoin Analysis & Visualization

This directory contains scripts for analyzing stablecoin transaction data from the Ethereum blockchain and creating comprehensive visualizations.

## Overview

The analysis tracks stablecoin transactions across multiple dimensions:
- **Volume**: Daily transaction volumes for each stablecoin
- **Transaction Count**: Number of transactions per day
- **Different Addresses**: Unique addresses involved in transactions
- **DeFi/ROLLUP Activity**: Transactions interacting with major DeFi protocols and Layer 2 rollups

## Files

- `stats.py` - Main script that extracts stablecoin transfer data from Ethereum blockchain
- `plots.py` - Creates comprehensive plots from the CSV data generated by stats.py
- `requirements.txt` - Python dependencies

## Usage

### 1. Extract Data
First, run the stats.py script to extract stablecoin transfer data:

```bash
# Analyze all stablecoins
python stats.py --all

# Or analyze specific stablecoins
python stats.py --usdc --usdt --dai
```

This will generate CSV files for each stablecoin:
- `{stablecoin}_daily_stats.csv` - Daily aggregated statistics
- `{stablecoin}_transfers.csv` - Individual transfer records

### 2. Create Visualizations
After running stats.py, create the plots:

```bash
python plots.py
```

This will generate four PNG files:
- `stablecoin_volume_plot.png` - Daily transaction volume for all stablecoins
- `stablecoin_transaction_count_plot.png` - Daily transaction count for all stablecoins
- `stablecoin_different_addresses_plot.png` - Daily unique addresses involved
- `stablecoin_defi_rollup_transactions_plot.png` - Daily DeFi/ROLLUP protocol transactions

## Configuration

### Block Range
Edit the configuration in `stats.py`:
```python
START_BLOCK = 22700000   # June 14th 2025
END_BLOCK = 23298000     # Sept 5th 2025
```

### RPC Endpoint
Configure your Ethereum RPC endpoint:
```python
RPC_URL = "http://localhost:8545"  # Your Ethereum node
```

### Performance Settings
- `BLOCK_BATCH_SIZE = 100` - Number of blocks to query concurrently
- `CHUNK_SIZE = 10000` - Number of blocks to process before writing to CSV (memory optimization)

## Memory Optimization

The analysis uses chunked processing to handle large datasets without memory crashes:
- Processes blocks in chunks of 10,000
- Writes data incrementally to CSV files
- Clears memory after each chunk
- Suitable for analyzing months of blockchain data
