3. Use a staging table + one set-based call (best for performance)
Instead of running the procedure per-row, COPY into a temp staging table, then process in bulk:
pythoncur.execute("CREATE TEMP TABLE staging (LIKE my_table) ON COMMIT DROP")
cur.copy_from(buf, "staging", columns=("id", "value", "timestamp"))

# Move to real table and process in one shot
cur.execute("""
    WITH inserted AS (
        INSERT INTO my_table SELECT * FROM staging
        RETURNING *
    )
    SELECT my_procedure(id, value, timestamp) FROM inserted
""")

conn.commit()
This avoids per-row round-trips entirely — the procedure still runs per row but inside a single query execution on the DB side.
